# 46 - 剥离形式主义外壳、主界面五大极简入口与设置中枢真实化治理 (Knowledge Base #46)

## ① 知识点与问题背景 (Context & Problem Statement)

在客户端 AI Coding 产品的演化过程中，极容易陷入“功能不够、入口来凑”的外壳膨胀误区：
1. **活动栏入口过度臃肿**：活动栏放置了 8 个图标，包括仅支持 Go 的 AST 拓扑、本地纯字符估算的用量看板、重复打开设置的 MCP 按钮等。用户会本能地按正式图标预期全套能力，结果发现不是全语言、不能导航、重启就丢数据，产生强烈的被欺骗感；
2. **终端第二页存在假 Trace 伪流水**：终端抽屉划出一个“Agent 执行链路”页签，本质上只是前端 UI 组件自身调用 `pushAgentTrace` 输出的几个时间戳片段，并非 Go 微内核真实的底层分布式追踪日志；
3. **顶栏形式主义徽章无实际拦截力**：顶栏放置“📜 宪法: X项”徽章，只是统计启用了几条规则，既不能保证大模型 100% 遵从，也不能在违规时实施阻断，徒增界面噪音；
4. **设置面板充斥硬编码“已开启”假状态**：安全沙箱面板画了三行“已开启”状态，然而底层根本没有开放也不应该开放关闭开关，把底层不可降级的物理防线画成了假装可管理的前端说明书；关于页面还附带未打通真实升级机制的“检查更新”按钮与粗糙的本地算术“费用估算”。

---

## ② 核心原理与知识内容 (Knowledge Content & Root Cause)

### 1. 视线与认知负荷：外壳与真内核的错位
开发者打开工具的第一眼是界面的外壳。
当真内核的能力主路径是“聊天 ➔ 算子调度 ➔ 写盘 ➔ Diff/Git 审查”时，外壳上多出的图谱、审计、用量等半成品入口，大幅稀释了主路径的注意力，抬高了不切实际的预期。
**真正专业级 Coding 工具的精髓在于减法**：把不成熟、不可靠、非通用的功能降级收纳，让主路径（对话、文件、Git、终端、设置）呈现绝对的纯粹与可预期性。

### 2. 真实防线 vs 假管理页面
沙箱隔离、高危指令物理拦截、敏感凭据剥离，是 Go 微内核与 SafetyRail 的底层安全基石，属于系统级“刚性防线”。
将它们设计成带有“已开启”字样与类似开关列表的界面，会给用户造成“这难道可以关闭？”或“这是前端伪造的”误解。正确的做法是作为不可篡改的架构机制进行诚实清晰的说明。

## ③ 标准解决方案与实操步骤 (Actionable Solutions & Step-by-Step Guide)

### 1. 活动栏收敛至五大核心真实入口
在 `ActivityBar.vue` 中仅保留：
- `💬 对话` (AI 对话工作台)
- `📁 文件` (工程文件资源管理器)
- `🌿 Git` (Git 变更与代码审查)
- `$_ 终端` (集成静默终端)
- `⚙️ 设置` (系统设置中枢)
彻底移除图谱、用量、MCP 冗余按钮。

### 2. 终端抽屉回归纯粹命令行
在 `TerminalDrawer.vue` 中彻底删除 `activeTerminalTab === 'logs'` 容器及顶部切换按钮，使终端抽屉成为纯粹的 powershell/cmd 交互控制台，杜绝前端假流水账。

### 3. 清理顶栏徽章与斜杠假功能
- 在 `ChatCockpit.vue` 顶栏移除 `📜 宪法: X项` 按钮与无用的宪法弹窗代码；
- 在 `workbench.ts` 中，从 `Ctrl+K` 移除“打开知识图谱”，从 `/` 候选指令中移除无实效的 `/audit` 字符串匹配审查。

### 4. 重构设置中枢（真内核、真设置）
在 `App.vue` 设置模态窗中：
- 将安全沙箱页重构为“🛡️ 内核级受控安全防线”，以清晰的三段式文本详述路径隔离、高危熔断与密钥剥离机制，剔除三行假开关；
- 关于页剔除“费用估算”与无效的“检查更新”，仅保留真实运行时信息与“导出系统诊断包”；
- 开辟二级选项卡「🧪 实验特性」，收纳 Go AST 拓扑与本地用量概览，向用户坦诚说明其局限性与实验状态。

## ④ 避坑指南与最佳实践 (Troubleshooting & Best Practices)

1. **切忌为了“界面充实”堆砌假控件**：如果一个功能不是开发者的日常刚需，或者尚未具备跨项目成熟度，绝不要赋予其一级入口地位；
2. **明确“不可配置安全机制”的呈现方式**：安全拦截若为内核级刚性规则，应当以安全架构说明书形式呈现，严禁使用开关、复选框或假状态灯进行装饰；
3. **功能必须可闭环、可交代**：一个按钮点了之后如果没有完整闭环（如只能弹 toast、没有实际执行逻辑），必须坚决剔除。
